- (idea by user) .NET 10 + Aspire + K8s + Azure deployment as the target migration path for the e-commerce microservice project
- (idea by coach) Path A: Aspire + Azure Container Apps — low ops, native Aspire target, serverless containers, KEDA autoscaling, built-in Dapr, Azure-only lock-in
- (idea by coach) Path B: K8s (AKS) + Dapr + skip Aspire — industry standard, multi-cloud portable, max control, deep learning curve, high ops burden
- (idea by coach) Path C: Hybrid — Aspire for local dev, K8s + Dapr for production, best DX + production power, dual config maintenance cost
- (decision) Chose Path A: Aspire + Azure Container Apps as the primary migration direction
- (decision by user) Messaging: Azure Service Bus + Dapr pub/sub for Saga/Ordering
- (decision by user) Database: Azure SQL MI + per-service DB (lift-and-shift)
- (decision by user) Gateway: Keep YARP in ACA
- (question) Identity: user asked 'thứ gì đang trend' — need to clarify trending identity options: Entra External ID vs B2C vs standard Entra ID
- (decision by user) Identity: Entra External ID for customer-facing auth
- (decision by user) CI/CD: GitHub Actions + azd (Aspire native deploy)
- (decision by user) Observability: App Insights + Aspire OpenTelemetry export
- (decision by user) Service-to-service auth: Managed Identity instead of JWT shared keys
- (decision by user) Testing: Aspire Testing (DistributedApplication) for Saga/Ordering integration tests
- (decision by user) Distributed cache: Azure Cache for Redis
- (technique) started architecture roast and adversarial review of both projects
- (decision by user) .NET 10 migration is confirmed and non-negotiable
- (decision by user) Saga: Rewrite to MassTransit Saga State Machine with Azure Service Bus
- (decision by user) DDD: Incremental — add DDD/CQRS for Inventory + Payment, keep Product/Customer/Basket CRUD
- (decision by user) Payment.API: Integrate properly into solution + compose, wire up consumers, implement real gateways
- (decision by coach) Auth: Best practice = Managed Identity + Entra External ID. Drop IdentityServer + symmetric JWT. Azure-native, no secrets to manage between services.
- (decision by user) Testing: Full TDD — unit + integration tests, 80% coverage target
- (decision by user) Database: Keep per-service DB (7 DBs), proper microservice isolation
- (decision by user) Gateway: YARP (code-first) replacing Ocelot
- (decision by user) PropertyViewings: ignore, sample project only
- (decision by coach) Python services: Keep as polyglot containers. Aspire AddContainer/AddDockerfile. Deploy as ACA containers alongside .NET. Polyglot is normal, no need to rewrite.
